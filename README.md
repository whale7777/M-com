# 민혁닷컴 설치 안내 (v4 · 새 디자인 + M포인트)

PyNest 와 **같은 Supabase 프로젝트**를 쓰기 때문에, PyNest 의 ID·비밀번호로 그대로 로그인돼요.
(Firebase 는 더 이상 필요 없어요.)

| | 어떻게 연동되나 |
|---|---|
| 로그인 | PyNest 의 ID / 비밀번호 그대로 |
| 관리자 | PyNest 에서 `role = admin` + 승인된 선생님 계정이면 자동으로 관리자 |
| M패스 | 관리자가 **PyNest ID** 를 입력해서 부여 (또는 "PyNest 승인 학생 자동 M패스" 설정) |
| 사용 중지 계정 | PyNest 에서 "사용 중지"한 계정은 민혁닷컴도 로그인 불가 |

## 0. 미리보기 (설정 없이)
사이트 주소 뒤에 `?demo` 를 붙이면 가짜 데이터로 모든 기능(관리자 패널 포함)을 눌러볼 수 있어요.
로컬에서는 폴더에서 `python -m http.server 8000` → `http://localhost:8000/?demo`

## 1. 데이터베이스 설정 (딱 한 번)
1. Supabase 에서 **PyNest 와 같은 프로젝트**를 열어요.
2. 왼쪽 **SQL Editor → New query**
3. `schema.sql` 내용을 통째로 붙여넣고 **Run** → `Success` 가 뜨면 끝이에요.
   - **v3 를 이미 실행했어도 한 번 더 실행하면 v4 로 업그레이드돼요.** (기존 자료·M패스는 그대로)
   - 여러 번 실행해도 안전해요. PyNest 의 기존 표(`profiles` 등)는 건드리지 않아요.
   - v4 에서 새로 생기는 표: `mh_points`(잔액), `mh_ledger`(내역), `mh_purchases`(구매), `mh_charges`(충전 신청)

## 2. `config.js`
이미 PyNest 의 Supabase 주소/키가 들어 있어요. `CONTACT`(문의처)만 원하면 바꿔요.
`ALLOW_SIGNUP: false` 로 바꾸면 민혁닷컴에서는 가입을 막고, PyNest 에서만 가입하게 할 수 있어요.

## 3. GitHub Pages 에 올리기
1. **새 저장소**(Public)를 만들어요. (PyNest 저장소와 따로!)
2. `index.html`, `style.css`, `config.js`, `app.js`, `admin.js`, `backend.js`, `state.js`, `defaults.js`, `util.js` **9개**를 올리고 Commit.
   (v3 에서 올린 저장소라면 같은 이름은 덮어쓰고 새 파일을 추가하면 돼요. `schema.sql`, `README.md` 는 안 올려도 돼요.)
3. **Settings → Pages → Branch: main / (root)** → Save
4. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 에서 열려요.

> PyNest 와 민혁닷컴이 같은 `아이디.github.io` 아래에 있으면 **로그인 세션도 같이 공유**돼요.
> (PyNest 에 로그인돼 있으면 민혁닷컴도 이미 로그인 상태. 한쪽에서 로그아웃하면 다른 쪽도 로그아웃돼요.)
> 나중에 민혁닷컴에 따로 도메인을 붙이면 세션은 따로지만 ID/비밀번호는 같아요.

## M포인트 · 홈 · 상세 페이지 (v4 새 기능)
- **페이지**: 홈(`#/`) · 전체/과목/단원 목록 · 자료 상세(`#/f/ID`) · 내 정보(`#/me`) · M포인트 충전(`#/points`) · M패스 안내(`#/pass`) · 이용안내(`#/about`)
- **홈 배너**: 관리자 → 홈 배너 탭에서 제목·문구·색·연결 주소·순서·표시 여부 수정. 기본 3개(M패스 / M포인트 / PyNest 광고). PyNest 주소는 `config.js` 의 `PYNEST_URL`.
- **M포인트 흐름**: 자료마다 **M포인트 가격**을 정해요 → 회원이 상세 페이지에서 `구매하기` → 포인트가 차감되고 문제·해설 PDF가 열려요(한 번 사면 계속).
  - 가격 0 + 프리미엄 = **M패스 전용** / 무료 자료에 가격 = **해설 PDF 판매가**
  - **M패스 보유자·관리자는 포인트 없이 전부** 열려요 (M패스는 "전체 이용권", M포인트는 "낱개 구매")
  - 구매·차감은 서버 함수(`mh_buy_file`)에서만 처리돼서 브라우저에서 포인트를 조작할 수 없어요.
- **충전 방법 (결제 대행 없이 수동)**: 회원이 `충전 신청`(금액 선택 + 입금자명) → 입금 확인 → 관리자 → **M포인트 탭에서 `승인`** → 즉시 포인트 지급. 이중 승인은 서버가 막아요.
  - 관리자는 ID로 포인트를 직접 지급/차감할 수도 있어요(여러 명 한 번에, 이벤트·환불용).
  - 계좌 안내와 충전 상품(예: `3000 | 3,000원`)은 **사이트 설정**에서 바꿔요.
- 환불 기능은 따로 없어요. 구매 취소가 필요하면 포인트를 직접 지급해서 돌려주면 돼요.

## 가입하면 PyNest 도 바로 사용 (v4.1)
- 민혁닷컴에서 가입한 계정은 PyNest 에서도 **자동 승인**돼서 같은 ID·비밀번호로 바로 로그인돼요. (schema.sql 을 다시 한 번 Run 해야 켜져요)
- 관리자 → 사이트 설정의 **"PyNest 자동 승인"** 체크로 끌 수 있어요. 끄면 PyNest 는 예전처럼 선생님이 승인해야 해요.
- PyNest 에서 가입한 사람은 승인 전에도 민혁닷컴에는 로그인할 수 있어요.
- ⚠️ 켜 두면 누구나 가입해서 PyNest 강의·문제까지 볼 수 있어요. 수강생만 쓰게 하려면 꺼두세요.

## 메뉴 패널 · 사이트 이동 버튼
- 왼쪽 위 **☰** 를 누르면 작은 메뉴 패널이 옆에서 열려요. 관리자 → **메뉴** 탭에서 항목 추가·이름·이모지·링크·순서·숨김을 바꿔요.
  - 종류: 링크 / 구분 제목 / 과목·단원 자동 목록(과목·단원 탭에서 만든 과목이 자동으로 들어감)
  - 링크에 `@pynest` 라고 쓰면 `config.js` 의 `PYNEST_URL` 로 연결돼요.
- 헤더 오른쪽 🐍 버튼과 패널 맨 아래 "사이트 이동"에서 PyNest 로 갈 수 있고, PyNest 쪽에는 🛒 민혁닷컴 버튼이 있어요(`pynest-shop-button.zip`).
- 주소는 대소문자를 구분해요: `config.js` 의 `PYNEST_URL`(…/PYNEST/), `MCOM_URL`(…/M-com/).

### 자료 올리는 순서
1. PDF 를 구글 드라이브에 올리고 공유 → **링크가 있는 모든 사용자 / 뷰어**
2. ⚙️ 관리자 → 자료 → ＋ 새 자료 → 링크 붙여넣기
   - **해설 PDF**: 넣으면 "📝 해설 받기" 버튼이 생겨요. 무료 자료여도 해설은 **M패스 전용**
   - **미리보기**: 샘플 1~2문제 PDF/이미지. 누구나 볼 수 있으니 팔 내용은 넣지 마세요!

3. 버튼을 누르면 드라이브 화면 없이 바로 다운로드

## 5. M패스 주는 법
- **개별 부여**: ⚙️ 관리자 → M패스 → PyNest ID 입력(여러 명은 줄바꿈/쉼표) → 만료일(선택) → 부여
  - PyNest 에 가입된 ID 만 부여돼요. 없는 ID 는 "가입 안 된 ID" 로 알려줘요.
- **자동**: 사이트 설정에서 "PyNest 승인 학생은 자동으로 M패스"를 켜면, PyNest 에서 승인된 학생은 전부 프리미엄·해설이 열려요.
  (민혁닷컴에서 가입만 하고 PyNest 승인은 안 받은 사람은 해당 안 돼요.)

## 알아둘 점
- **민혁닷컴에서 가입한 사람은 PyNest 회원 목록에 "승인 대기"로 나타나요.**
  PyNest 관리자 → 회원 탭에서 **승인을 누르면 그 사람이 PyNest 강의 사이트도 쓸 수 있게 되니**, 수강생이 아닌 사람은 승인하지 마세요.
  (이게 불편하면 `config.js` 의 `ALLOW_SIGNUP` 을 `false` 로.)
- 프리미엄 링크(문제·해설)는 소스에 안 들어 있고, M패스가 있는 계정만 서버에서 받아가요.
  다만 **받은 사람이 파일 자체를 퍼뜨리는 건 막을 수 없어요.** (완전 차단은 워터마크/유료 결제 시스템이 필요)
- 다운로드 수는 누구나 +1 만 할 수 있게 열어둔 값이라 통계는 참고용이에요.
- 무료 Supabase 프로젝트는 일주일쯤 아무도 접속하지 않으면 일시정지돼요. PyNest 와 같은 프로젝트라 둘 다 영향을 받아요.
- 과목을 지우면 그 자료는 "미분류"로 남아요. 같은 이름으로 다시 만들어도 자동 연결은 안 돼요.
- 100MB 넘는 파일은 드라이브 정책상 바로 다운로드가 안 될 수 있어요.
- GitHub Pages 약관의 상업적 이용 제한은 직접 확인하세요. 유료 판매를 본격적으로 하면 Cloudflare Pages / Netlify 같은 곳으로 옮기는 걸 추천해요.
- 계정(ID)을 받으니까 개인정보처리방침 페이지는 따로 준비해두는 게 좋아요.

- **schema.sql 전체를 다시 실행**하세요 (Success 나오면 됨). 비공개 버킷 `mh-files`, 스토리지 정책, `mh_notices` 테이블이 만들어져요. 여러 번 실행해도 안전해요.
- 관리자로 로그인 → 과목/단원 페이지(예: 생물 › 유전) 맨 위 **＋ 이 단원에 자료 올리기** 버튼 → 과목·단원이 미리 선택된 등록 폼이 열려요.
- 문제 / 해설 / 미리보기 각각 **없음 · 드라이브 링크 · 파일 업로드(PDF)** 중 고를 수 있어요. 업로드는 Supabase Storage(비공개)에 저장되고, 다운로드는 권한을 확인한 2분짜리 임시 주소로 나가요.
- 공지사항: ☰ 메뉴 › 공지사항, 홈에도 최근 공지가 보여요. 관리자는 글쓰기/수정/삭제/📌고정/숨김.
- 업로드 용량 한도: config.js `MAX_UPLOAD_MB`(기본 10), 버킷은 10MB. 파일당 2MB 안팎이면 충분해요.
- 파일 전체를 올릴 때 index.html, *.js, style.css 모두 같이 올려야 해요 (`?v=7` 캐시 버전).

## v6 — 폴더형 단원 (족보 스타일)
- 관리자 › 과목·단원에서 단원마다 **＋하위** 로 안에 폴더를 계속 만들 수 있어요 (큰 단원 › 범위 › 소단원 …). ↑↓로 순서, ✕로 삭제. 저장 버튼을 눌러야 반영돼요.
- 과목/단원 페이지는 폴더형으로 보여요: 접었다 펼 수 있는 폴더, 맨 끝 폴더는 네모 칸 안에 `01회 ⬇ 02회 ⬇` 식 회차 칸. 자료 제목을 "01회"처럼 지으면 숫자순으로 정렬돼요.
- 자료 등록 시 단원은 어느 깊이든 고를 수 있어요 (맨 끝 폴더 권장). 폴더 칸의 "＋ 자료" 버튼으로 그 폴더에 바로 올릴 수 있어요.
- 잠긴(프리미엄) 칸은 🪙/🔒 아이콘이고 누르면 상세 페이지로 가요. 열린 칸은 ⬇로 바로 다운로드돼요.
- 기존 목록 보기는 "☰ 목록으로 보기"로 계속 쓸 수 있어요. DB(SQL) 변경은 없어요.

## v7 — M패스 건수제 · 연필 수정 · 새 자료 페이지
- **schema.sql 전체를 다시 실행**하세요 (기존 자료 등급도 가격에 맞게 자동 정리돼요: 가격 0 → 무료, 1 이상 → 프리미엄).
- M패스 = 기간권 + 받을 수 있는 건수 (1건 = 자료 1개, 문제+해설 함께). 기본 플랜(1P = 1원, 문제 1세트 300P 기준):
  45일 15건 3,900P · 90일 35건 8,400P · 6개월 80건 17,600P · 12개월 180건 36,000P. 관리자 › 사이트 설정 › "M패스 플랜"에서 수정.
- 학생은 M포인트로 패스를 구매(구매 시 기간·건수가 이어짐)하고, 자료 상세에서 "M패스로 받기"로 1건씩 써요. 받은 자료는 구매한 자료처럼 계속 다시 받을 수 있어요.
- 관리자 › M패스 탭: 플랜 선택 → 만료일·건수 자동 입력, +10건/+1개월 버튼.
- 자료 수정은 설정 창 없이 자료 페이지에서 ✏️ 로: 제목·설명·가격·난이도·문항 수·과목/단원. 가격 0 → 무료, 1 이상 → 프리미엄 자동.
- "＋ 새 자료"는 자료 상세와 같은 모양의 새 페이지(#/new)에서: 제목 → 설명 → 가격 → 파일 업로드/드라이브 링크.

## v9 — 직원 권한 (OWNER / ADMIN / TEACHER / MOD) — 민혁닷컴 + PyNest 공용
- **`staff_roles.sql` 을 Supabase SQL Editor 에서 한 번 실행**하세요. 기존 표·정책·데이터는 건드리지 않고 "추가"만 해요. (여러 번 실행해도 안전)
- 원래 관리자(`profiles.role = 'admin'`, imadmin)는 자동으로 **OWNER** 예요.
- 역할은 ⚙️ 관리자 패널 › **👥 권한** 탭에서 PyNest ID 로 부여/변경/해임해요. 두 사이트에 같이 적용돼요.

| 역할 | 할 수 있는 일 |
|---|---|
| OWNER | 전부 + ADMIN 임명/해임 |
| ADMIN | 전부 (ADMIN 임명/해임·OWNER 변경 제외), TEACHER/MOD 임명 가능 |
| TEACHER | 자료·과목·단원(폴더)·파일 올리기/고치기 (PyNest: 강의·문제집·문제·숙제) |
| MOD | 관리만: 공지, M패스 부여, 충전/패스 신청 승인, 회원 승인/중지, 글·댓글 삭제 |

- 권한표를 바꾸려면 `staff_roles.sql` 의 `staff_can()` 과 `state.js` 의 `PERMS` 를 같이 고치세요.
- `staff_roles.sql` 을 아직 안 돌렸어도 사이트는 예전처럼 동작해요 (직원 역할만 안 보여요).
